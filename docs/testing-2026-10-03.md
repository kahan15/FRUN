The existing project was updated in place. The full Debug build and all **18 iOS XCTest cases passed again** after the latest profile changes, using Xcode 26.3, iOS Simulator SDK 26.2 and iPhone 17 / iOS 26.3.1. ## New fixes

- The sign-out confirmation previously displayed unrelated Privacy and Delete account actions. It now contains Sign out and Cancel only. Account deletion remains a separate profile action with its own password and confirmation flow.
- The profile's Sync now button now bypasses the automatic retry delay. A deliberate manual retry starts immediately when no other sync is running; automatic uploads keep their bounded retry schedule.

The old sign-out problem was reproduced in Simulator. The corrected source compiled and passed the existing XCTest suite. The final corrected dialog and immediate manual-retry behavior still need direct screen checks; simulator window input failed before those checks could finish. Existing XCTest cases cover core contracts/recovery and are not UI tests of these two buttons.

## Exact owner checks

1. Open the existing `ios/TerritoryRun.xcodeproj`, choose **TerritoryRun → iPhone 17**, then **Product → Run**. If a test API is no longer running, use the normal laptop development server described in the [production guide](production-roadmap.md); its simulator address is `http://localhost:8000`.
2. Sign in with a disposable account, open **You**, scroll down and tap **Sign out**. Confirm the dialog offers only **Sign out** and **Cancel**. Cancel must keep the account signed in.
3. For connection recovery, use only a disposable test session. Stop its API, press **Sync now**, and confirm the unavailable-server message. Restart the same API and press Sync now again; it should attempt immediately and return to Connected. Do not stop another person's service or delete database volumes.

### **DESTRUCTIVE TEST — DISPOSABLE ACCOUNT ONLY**

The next check permanently erases the selected account's active server records and its saved/unfinished runs on this phone. Use only an account created specifically for deletion testing, with no wanted data. Its data goes to the configured local server; this is not a public upload or purchase.

4. Open **You → Delete account**. Try a wrong password: the account must remain usable. Then use the correct password and confirm deletion. The app should return to sign-in; the old account must no longer sign in. Record the exact error or unexpected screen if either check fails.
5. Connect a physical iPhone and complete the [device checklist](device-checklist.md), recording results in the [evidence sheet](device-evidence.md). Complete Apple Account, trust, Developer Mode and Personal Team prompts yourself. Do not purchase enrollment for these local checks.

## Environment and release status

Backend code was unchanged in this pass. October 1's **67 backend tests**, real HTTP runtime smoke, **31 native Swift core checks** and **7 script tests** remain the latest results for those components. October 3's iOS test rerun used the final profile source changes.

No hosting, Apple enrollment, public deployment, App Store upload or public source sharing was performed. Existing application data and other Docker projects were not changed. The app is not ready for App Store submission: physical-device acceptance, account recovery, abuse controls, retention/deletion-aware restore, production operations and owner launch-policy decisions still remain. Follow the [production roadmap](production-roadmap.md).
